# Agent Note: 重复代码门禁

Status: implemented

<a id="problem"></a>

## Problem

`src/` 下的重复片段没有可执行的判定。评审者只能凭印象指出相似代码，同一处重复是否已存在、新增了多少，都没有稳定的答案；重构或搬移文件后，更难分辨重复是变多还是变少。

<a id="decision"></a>

## Decision

`scripts/verify-duplication.ts` 用 jscpd 扫描 `src/`，把结果与 `duplication-baseline.json` 逐条比对，出现基线之外的克隆即以退出码 1 失败。门禁注册在 `pnpm run verify-all` 的注册表里，与文档门禁同一入口。

- **指纹**由文件对、片段行数与片段内容摘要构成，不含行号。文件对按字典序拼接，两侧片段摘要也按字节序拼接，因此指纹与 A/B 归属无关，无关改动不会让基线失效。
- **片段摘要**先归一化行尾再计算，同一片段在 CRLF 与 LF 检出上得到同一指纹。
- **行数**取两侧跨度的较小值并取绝对值，jscpd 对跨嵌套结构的克隆会给出两端倒置的行号。
- **比对按出现次数**而非存在与否。jscpd 把一处重复按相邻窗口拆成多条克隆，只比对存在与否会让基线随首处重复的克隆条数变化而误判。
- **扫描格式**同时列 `typescript` 与 `tsx`。`.tsx` 不属于 `typescript` 格式，只列前者时组件文件整体不参与比对。
- **基线只允许调低。** 无法消除的重复用 `pnpm run verify-duplication -- --update` 调高，并在提交信息里说明理由；改扫描参数会让既有基线整体失效，脚本遇到参数不符即失败并要求重写。

<a id="baseline-state"></a>

## 基线现状

基线为空，`src/` 当前没有任何达到阈值的重复，门禁在 `verify-all` 中通过。新增重复会直接失败，没有可落进去的既有指纹。

<a id="alternatives-considered"></a>

## Alternatives considered

**按百分比阈值判定。** 克隆占比随文件量变化而漂移，一处真实的重复可能被总量稀释到阈值以下；阈值本身也没有可复核的来源。

**只列 `typescript` 格式。** 少配一项就少覆盖全部组件文件，门禁对 `.tsx` 静默失明，且不产生任何提示。

**把基线一次性冻结成引入时的 29 处重复。** 门禁立刻变绿，但 29 处重复同时被登记为可接受，后续新增的重复只要落在这些指纹里就无人追问。

<a id="consequences"></a>

## Consequences

门禁需要 `jscpd` 作为开发依赖，扫描 `src/` 全量，随文件数增长而变慢。

基线为空时，任何一处新增重复都会失败且必须就地消除：这是最严格的状态，也让 `--update` 的正当用途只剩"确认无法消除后冻结残余"。
